# Repo review after the 2026-10-29 iterations (2026-10-30)

Three independent reviewers, same prompt (engineering solidity, modem.ts cleanliness, whether the scorecard
predicts real hardware, multi-device simulation, next priorities, correctness/security risk from the day's churn):
Codex (default model, medium reasoning), Gemini 4 Argon (medium, via `agy`; timed out at 10 min with its answer
mostly written), Grok 4.7 (medium, via `cursor-agent`). Each read the code and ran probes. Claims below marked
**verified** were re-checked in this session against the code.

## Consensus findings, ranked

1. **Carrier sense is blind to rotated tone sets** (all three; **verified**, `src/modem.ts` `busy()`). It scores tone
   set 0 only; with `rotate: 3` two of every three body symbols sit between set-0 bins, so `busy()` returns false
   mid-frame (Codex: `true,false,false` repeating on dual/robust; Gemini: 54% true on voice/fast). Listen-before-talk
   in `browserAudioLink` can therefore start over a live frame. The timed room never calls `busy()`: it uses god-view
   `active.some(...)`, so the "0 overlapping frames" result does not test the shipping carrier sense.
2. **The on-air format changed with no version** (all three; **verified**). `barSymbols` default 8 → 1 (commit
   `34cdc3f`), parity 16 → 32 and rotation on several presets, `music` `alt: 2`, `chime`'s second scale, `tune`'s
   alternation. Two builds a day apart cannot talk; nothing in the sync/header/handshake says which schedule is in
   use. Not a crypto issue; an interoperability one.
3. **"No options" is not `PRESETS.voice`** (Codex, Grok; **verified**, `config()`): omitted options give rotate 1 /
   parity 16, the voice preset is rotate 3 / parity 32, and the two cannot decode each other. `test/room-time.ts`
   and several modem tests run the no-options modem, so the only multi-node test exercises a modem the browser
   never ships.
4. **The retry path re-reads the length with `lengthAt`, not `lengthsAt`** (all three; **verified**, `tryHead`):
   after retuning, only the plain vote is tried, so the differential candidate that item 28 added is lost exactly
   on the path that needs it (reverb plus drift). Also from Codex: a frame whose head is lost has no timing/pitch
   recovery (tail-only recovery decodes at nominal timing); a max-size robust frame at 3000 ppm with its first 16
   symbols erased gave zero deliveries. Gemini: every `(offset, len)` candidate of a failed frame is queued for a
   retry, so a corrupted frame fans out into many retries (CPU spikes on phones).
5. **`tonesAt`/`goertzel` have no bounds check** (Grok, Codex): a window before `buf[0]` or past the end produces
   NaN energies that are cached under that key. Differential mode reads one symbol back; a late-join cut with the
   sync at sample 0 hits it.
6. **The scorecard cannot yet say what will happen on hardware** (all three). Specific problems: the radio row is
   two gentle biquads plus AGC (Grok measured −14 dB at 4–7 kHz through the filter and the frame still decodes),
   so "hidden passes a radio" is not shown; the room bank ignores `--seed`, so other seeds reuse the same rooms;
   80 reflections spread over RT60 makes 0.8 s *thinner* than 0.3 s for short symbols, which is why several presets
   score higher at 0.8 s (Gemini); collisions score only one sender; one payload size; constant drift; no device
   response, THD, limiter or browser scheduling; Wilson intervals at 30–100 trials cannot resolve 2–5 point moves,
   and overlapping intervals are not a paired test (use discordant pairs / McNemar on the same rooms, with held-out
   room and device groups). Several unit tests use `Math.random()`, so a red run is not reproducible.
7. **Browser capture** (Codex, Gemini): `announce.ts` has no dropped-buffer padding (`browser.ts` does); all
   decoders run on the main thread in a `ScriptProcessorNode`; `push()` copies the whole retained buffer every
   call (~6 MB per decoder for max robust at 48 kHz). The listener's mic stays open while its own speaker plays.
8. **Physically invalid test configs** (Codex): `test/transport.test.ts` runs tri/turbo at 16 kHz, above Nyquist
   for their bands; matched synthesis and detection round-trip the aliases. `config()` does not validate rates.

Checked and not a bug: the differential tap subtracts the previous window measured on the *current* set's bins,
which is the leakage that matters at those frequencies (Gemini flagged it as a set mismatch). State restore in
`tryHead` is complete on every path (all three). RS + CRC-32 still gate every delivery; no new forgery path; the
unsigned ACK/FIN/RST (threat T21) is unchanged.

## Refactors worth doing (and not)

Do: an explicit candidate lifecycle for `tryHead`/`flushPending`/`pending` (delivered / failed / waiting-for-sample,
one best candidate per sync cluster, `lengthsAt` everywhere); an explicit decode context for period/coefs/energies
instead of save-mutate-restore; write `barSymbols: 1` on every rotating preset so the default is not the wire
format; bounds-check `goertzel`; share capture/gap accounting between `browser.ts` and `announce.ts`; move
`src/ofdm.ts` out of `src/`.

Don't: split modem.ts into a codec framework, a class per preset, strategy objects per decode pass, or separate
TX/RX schedules. `setFor` stays the single shared contract.

## Multi-device simulation: yes

Extend `timedRoom` with a directed channel matrix (per sender→listener impulse response, attenuation, delay),
per-device clocks and noise, self-audio (a node hears its own speaker), and carrier sense driven by received samples
through the real `busy()`/`tailLeft()`. It would catch finding 1, hidden terminals, near/far capture, asymmetric
ACK paths, ladder fallback asymmetry, self-echo poisoning of `lastTailEnd`/`done`/repeater caches, and starvation
between connections. No geometric room model needed at first.

## Priorities the reviewers agree on

1. Fix `busy()` across sets; run the timed room on the shipping preset through the real carrier sense.
2. A frame-format version: a `v` in the handshake/preset name or a header bit, plus a compatibility fixture
   (a committed waveform per preset that must decode).
3. Defaults = `PRESETS.voice`; `lengthsAt` on the retry path; `goertzel` bounds; one retry per sync cluster.
4. A recorded corpus (phone↔laptop both ways, PA, quiet/lively/clipped, 44.1/48 pairs, a two-sender take, with
   failures kept), replayed through the demodulator in CI, split by device and session; paired statistics.
5. Scorecard realism: rooms keyed by seed with held-out banks, reflection density that scales with RT60, a
   speaker/mic response with a little THD, score both colliders, independent RNG streams per impairment.
6. Browser: padding in `announce.ts`, decoding off the main thread, bounded buffer copies, mute the local decoder
   while sending.

Stop until a recording shows the failure: more parity sweeps, more bands or faster symbols, OFDM integration,
more Chase, more points on this room bank. `tune` failing over the air while scoring 100% in simulation is the
case in point.
